# Stage 8 Compiler Fix — WebRTC Android bindings

## Fixed

- Removed compile-time references to `VideoCapturer` and `CameraVideoCapturer` because the `FsWebRTC.Bindings.Maui.Android 0.9.3.15` binding does not expose those Java types as the C# types used by the original implementation.
- Camera capture is still real WebRTC capture: `Camera2Enumerator.CreateCapturer(...)` is retained, while capturer lifecycle calls (`initialize`, `startCapture`, `stopCapture`, `dispose`) are invoked against the generated Java object.
- Camera switching now stops the active capturer and creates the opposite-facing camera. This avoids requiring `CameraVideoCapturer.ICameraSwitchHandler`.
- Changed EGL storage to `Org.Webrtc.IEglBase` and moved the legacy `EglBase.create()` factory call behind Java reflection, avoiding the C# obsolete warning while remaining compatible with the bundled libwebrtc.
- Updated all `ISdpObserver` and `PeerConnection.IObserver` implementations to match the nullable signatures generated by the binding.

## Package compatibility

The project remains on:

`FsWebRTC.Bindings.Maui.Android 0.9.3.15`

No second WebRTC package was introduced.

## Verification limitation

The editing environment does not contain the .NET SDK / Android workload, so a device build cannot be executed here. The source was checked for the reported missing symbols and nullable implementation mismatches.
